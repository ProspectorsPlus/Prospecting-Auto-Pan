Getting started

This page covers the path from a fresh download to a working install of Prospector Lite 5.0.0: verifying the file, the unsigned first launch on macOS and Windows, the Welcome screen, and the five-page setup wizard. It ends with where the app keeps its data and what to set up next.

What Prospector Lite is

Prospector Lite is a free desktop macro for the Roblox game Prospecting. It automates the pan, dig, and shake loop by reading pixels from your screen and sending ordinary keyboard and mouse input through the operating system; it never touches the Roblox process, its memory, its files, or its network traffic.

Version5.0.0, released 2026-08-08

Both platforms can also run the app from source (Python 3.11 or newer; 3.13 tested). One caution before you start: no macro is risk-free. Using automation may violate the Roblox Terms of Use, and Prospector Lite makes no claim of undetectability. Use it at your own discretion.

Download and verify

Official downloads exist in one place: the v5.0.0 GitHub release. A copy from anywhere else should be checksum-verified against that release before you run it. The files you need:

Verify the SHA-256 checksum

Both builds currently ship unsigned (no Apple Developer or Authenticode certificate yet), so the checksum is the integrity mechanism. Download SHA256SUMS.txt into the same folder as your build, open a terminal in that folder, and run the command for your platform:

PlatformCommandResult to expect
macOS (Terminal)shasum -a 256 -c SHA256SUMS.txt --ignore-missinga line ending in OK for the file you downloaded
macOS, single fileshasum -a 256 ProspectorLite-5.0.0-macos-arm64.dmga hash to compare by eye against SHA256SUMS.txt
Windows (PowerShell)Get-FileHash .\ProspectorLite-5.0.0-Windows-x64-Setup.exe -Algorithm SHA256a hash to compare against the matching line in SHA256SUMS.txt (swap in the portable ZIP name if that is what you downloaded)
Every character must match. A mismatch means the file is not the released build; do not run it. Delete it and download again from the release page.
After installing, you can cross-check identity from inside the app: the Trust Center tab's Build identity section shows the version and the build commit, which must match the release. See Trust and permissions.

First launch on macOS

The macOS build is unsigned and not notarized, so Gatekeeper will warn that the app is from an unidentified developer the first time you open it. That warning is expected. Once the checksum matches, use the right-click flow:

  1. Open the DMG and drag Prospector Lite into Applications.
  2. In Applications, right-click (or Control-click) the app and choose Open.
  3. In the dialog that appears, click Open. macOS remembers the choice, and later launches open normally with a double-click.
Never disable Gatekeeper. Prospector Lite never asks you to, and any software that does is a red flag.

The three permissions at a glance

macOS asks for three permissions, and only these three. The setup wizard explains and tests each one before macOS shows any prompt; checking status never triggers a prompt by itself, and a system dialog appears only after you click a card's Request access… button.

Card in the appmacOS paneWhat it is for
"Screen Detection"Privacy & Security → Screen RecordingReads pixels of your screen to see the game's bars and prompts. Calibration stores coordinates and reference colors, not images. Newer macOS labels this pane "Screen & System Audio Recording"; the app captures pixels only and contains no audio code.
"Keyboard & Mouse Control"Privacy & Security → AccessibilityPresses ordinary keys and mouse buttons, like a person would. Output only; it does not observe your input.
"Safe Stop & Global Hotkeys"Privacy & Security → Input MonitoringListens for your configured control keys (Esc, Ctrl+K and the other stop chords) so Safe Stop always works, even while Roblox has focus. It matches configured chords only and keeps no keystroke log.

A missing permission only ever blocks the Start macro button; the app, its settings, and the documentation stay fully usable. One macOS quirk worth knowing up front: Screen Recording and Input Monitoring grants apply at process launch, so after granting one the app may report that a restart is needed and offer a Restart Prospector Lite button. Quitting fully and reopening has the same effect.

The deep detail (what each capability can access, what is kept on disk, in-app tests, and how to revoke) lives on Trust and permissions.

First launch on Windows

The installer is per user: it needs no administrator rights, shows no UAC prompt in normal use, and installs no services, drivers, or scheduled tasks. The portable ZIP is a second option that installs nothing at all; unzip it anywhere and run the executable inside.

Because the build is not Authenticode-signed yet, SmartScreen has no reputation for it and will likely show "Windows protected your PC" on first run. That is a reputation warning, not a malware verdict. The order matters:

  1. Verify the SHA-256 checksum first (see above).
  2. When the SmartScreen dialog appears, click More info.
  3. Click Run anyway.
Never disable SmartScreen or your antivirus, and never trust software that tells you to. If Windows Defender flags the download, verify the checksum and report the false positive; do not switch protection off.
Do not run Prospector Lite as administrator. If Roblox runs as administrator and Prospector Lite does not, Windows silently drops the synthetic input; run both at the same normal level (neither needs admin).

Windows has no permission model for screen capture or synthetic input from desktop apps, so there is nothing to grant and no prompt will appear. Instead, the wizard's Trust page provides real in-app tests (a screen capture, a sandboxed keystroke, a Safe Stop hotkey test) so you can prove each capability works on your hardware. One candid note the project ships in its own docs: the Windows build is produced and tested in CI but has not yet been runtime-verified by the developers on a physical Windows machine; those tests exist so you can verify on yours.

The Welcome screen

On a fresh install, Prospector Lite opens to the Welcome screen. It is onboarding only: there is no access code, no license check, and no account behind it.

The card states what the app is and makes four short commitments, quoted here by their bold labels:

  • "External only." It never injects into Roblox, never modifies the game or its files, and never reads game memory.
  • "Private by design." Data stays on this computer: no account, no access code, no analytics, and no network requests unless you set up optional notifications yourself.
  • "Permissions." A preview of the three macOS permissions above, with the promise that the next step explains and tests each one before macOS shows any prompt. Windows needs no admin rights.
  • "Safe Stop." Esc or Ctrl+K stops the macro instantly and releases every key and mouse button.

Your choices on this screen:

ControlDefaultWhat it does
Continue Marks Welcome as complete and opens the wizard at Trust & Permissions. Once setup is finished, the same button reads Open Prospector Lite instead.

"Show this screen at every launch"onKeeps Welcome as your launch screen even after setup.
"Skip the setup wizard automatically on launch"offLaunches go straight to the app. It can be turned off again from Welcome, the app Settings page, or the Trust Center.

Each checkbox saves immediately when toggled, and reverts with a visible error message if the save fails. The footer carries a build line (app name, version, build commit, platform) plus "Privacy & data" and "Security" links that open the shipped PRIVACY.md and SECURITY.md. You can reopen this screen any time from the Tutorial menu entry "Welcome, privacy & version"; after setup it also grows shortcut links such as "Review setup", "Review calibration", "Start tutorial", "Open the main app", and "Trust Center".

The setup wizard

The wizard's step rail lists five pages: "1 Welcome", "2 Trust & Permissions", "3 Guided Calibration", "4 Readiness Check", "5 Prospector Lite". Progress persists in onboarding_state.json inside the data folder and is written atomically, so a crash can never corrupt setup progress; the wizard resumes wherever it left off. You can re-run it any time from the Trust Center's Re-run setup wizard button, and re-running deletes nothing.

02

Trust & Permissions

A platform badge ("macOS detected" or "Windows detected") sits at the top, and the page promises: "Nothing is requested until you click a button below." Cards unlock in sequence, so there is always one highlighted card to do next.

  1. Work the required cards top to bottom. On macOS, click Request access… on the highlighted card, flip the switch in the System Settings pane it opens, then use the card's recheck button.
  2. Run each card's Test. The tests run the real capability: a small screen capture shown once and discarded, one keystroke posted into the app's own test field, and an 8-second listener that waits for you to press Esc or Ctrl+K.
  3. Watch the progress line ("Required permissions: N of 3 complete") reach 3, then click Continue to Calibration →.

On Windows the same page has no grant buttons, only tests: the footer notes there are no permission prompts here and asks you to run the tests to prove the capabilities work. On macOS the footer states you can continue at any time; Start macro simply stays disabled until the required permissions work.

03

Guided Calibration

Calibration teaches the app where the game's UI sits on your screen. The guided pages run the same calibration engine and the same save file as the Calibrate tab; there is one set of values, and the wizard just walks you through it without leaving setup.

  1. Open Roblox in Prospecting on your primary display, then press Detect Roblox window in the "Before you calibrate:" banner. Success reports the window's size and position. This is a prerequisite check, not a numbered step.
  2. Work the required items in order: "Pan capacity bar (right + left ends)", "'Pan' prompt pixel", "'Collect Deposit' prompt pixel", "'Shake' prompt pixel", and "Advanced cue matching" (three letter-shape masks captured from the live prompts).
  3. Optionally calibrate the extras for features you plan to use: "Green dig-bar pixel", "Money counter box", "Shards counter box", "Finds pop-up box", "Auto Pan button pixel".

Auto-calibration (on by default) places the required pixel items from a built-in profile each run, so they report "Auto" until you calibrate by hand, which makes them exact for your setup. "Advanced cue matching" is the exception: masks require a real capture and can never be auto-placed. The "Fortune River recovery (optional, advanced)" feature is deliberately not part of the wizard; it lives on the Calibrate tab only. The full walkthrough with example screenshots is on the Calibration page.

Prospector Lite

The wizard closes and the main app starts. By default the interactive tutorial opens on entry (the "Open tutorial whenever Prospector Lite opens" preference); it tours the tabs, the calibration surfaces, Safe Stop, and the Trust Center, and its footer checkbox can stop it opening automatically in future.

From here, the Start macro button on the Run tab is live as soon as the required permissions and calibration pass. If anything is still missing, the button stays disabled and the Run tab names the blocker.

Skipping the wizard

The Skip wizard button (on Welcome and in the wizard footer) opens a modal titled "Skip the setup wizard?" with four options:

OptionCaption (verbatim)What is stored
"Skip this time""Open the app now. Setup stays exactly as it is and the wizard can come back next launch."Nothing; a session-only flag.
"Mark wizard complete""Records the wizard as reviewed. Anything actually missing (permissions, calibration) still shows as a warning."The wizard state becomes finished, stamped as marked complete rather than walked through.
"Skip wizard automatically in future""From now on, launches go straight to the app. Explicitly opening Welcome still shows the wizard. You can turn this off in Welcome, Settings, or the Trust Center."The auto-skip preference; setup itself is not marked complete.
"Cancel" Nothing.

No skip option weakens the start gates. Whichever you choose, Start macro stays disabled until the required permissions and required calibration actually pass, readiness warnings keep reporting the true state, and the Run tab says what is missing. Skipping only changes what you see at launch, never what is checked.

The Readiness Check

Wizard page 4 runs a fresh set of probes and shows each as PASS, FAIL, WARN, or INFO. Results are computed live at the moment you look, never replayed from an earlier session. The rows:

RowWhat a pass looks like
Screen detectionmacOS: "Permission granted." Windows: "Verified by your own test this session."
Keyboard & mouse controlSame pattern: an OS grant on macOS, your own passed test on Windows.
Safe Stop hotkeysSame pattern; on Windows an untested capability shows an info row pointing at the Trust tab tests.
Roblox window"Roblox window found." A closed Roblox is informational only, never a FAIL; open it before your first run.
Required calibrationUser-calibrated items, or auto-calibration covering the required items with a note that manual calibration makes them exact.
Advanced cue matchingIts own row, so the mask requirement is visible; missing masks fail even when single-pixel fallback values exist.
Data folder"Writable:" followed by the data folder path, proven by a real write.
Settings save & reload"Atomic write + read-back verified." on a dedicated probe file.
Build identityThe version and commit of your build, for cross-checking against the release.
Network defaults"No network features enabled. Normal use is fully offline." (or an info row if you configured your own Discord webhook).
PlatformAn info row naming your operating system and architecture.

Every failing row gets a Fix now button that deep-links to the exact wizard step that fixes it, and a Details button that opens the warning drawer with the matching diagnostics. The page also offers Retest, Export diagnostics, Copy diagnostic summary, Open wizard log, Open data folder, and FAQ & troubleshooting buttons.

When all required rows pass, the page reports "Everything required passed. You are ready to prospect." and the footer button reads Finish setup →. If something still needs attention, the button reads Enter the app anyway →; you can always enter, and only Start macro stays disabled until the required items pass.

Where your data lives

Prospector Lite keeps a single data folder and writes nothing anywhere else; nothing is written into the app bundle either.

Install typeData folder
macOS (packaged app)~/Library/Application Support/Prospector Lite
Windows (installer or portable)%APPDATA%\Prospector Lite
Running from sourcenext to the scripts

The files you will most often care about:

FileContents
prospecting_config.jsonSettings and calibration
prospecting_builds.jsonSaved builds (full settings presets)
prospecting_scripts.jsonStudio block scripts
run_history.jsonThe last 100 runs with stats and stop reasons
run_logs/Full per-run engine logs
onboarding_state.jsonSetup wizard progress
onboarding.logWizard and diagnostics action log: operation names, status strings, and error codes only; rotates once at about 256 KB
prospecting_secrets.jsonLocal secrets (the optional Coach API key); kept separate from the config so it is never exported
instance_idA random local id; never transmitted

Deleting the folder removes everything: quit the app, delete the folder, and the app returns to a fresh first run. That folder is the entire data footprint on your computer. Because it lives outside the app, updates and reinstalls keep your settings, calibration, builds, and history; replacing the app never touches them. Two platform notes:

  • On macOS, uninstalling means deleting the app and, optionally, the data folder. No launch agents, kernel extensions, or privileged helpers are ever installed.
  • On Windows, the uninstaller deliberately keeps the data folder so a reinstall picks up where you left off; delete %APPDATA%\Prospector Lite by hand for complete removal.

If you used the old private "Prospectors Plus" app, the first run performs a one-time, copy-only import of its data (config, builds, scripts, history) and strips the legacy access-gate keys. The old folder is never modified, and the Welcome screen reports that the import happened. In-app, the Trust Center's "Local data" section offers scoped delete actions up to "Delete ALL local data…", which is double-confirmed and limited to the known files listed there.

What to do next

  1. Calibrate for your setup. Auto-calibration covers the required pixel items, but hand calibration makes them exact, and the three cue masks always need a real capture. The Calibration page walks through all of it with in-game screenshots.
  2. Learn the controls before the first run. The Safe Stop defaults are Esc to quit, Ctrl+K to start or stop, Ctrl+J to soft-stop, and Ctrl+L to pause; all are rebindable on the Keybinds tab, and stopping always releases held keys and mouse buttons first.
  3. Tune when you are ready. The Settings reference documents the tuning keys, and Modes and builds covers presets you can start from.
  4. Read the trust pages. Trust and permissions goes deep on what each permission can and cannot do, the in-app tests, and the Trust Center.
