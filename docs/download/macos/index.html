Install Prospector Lite on macOS

Five short steps: download two files, check the fingerprint in Terminal, drag the app into Applications, grant three permissions, and finish setup inside the app. Needs a Mac with an M1 chip or newer; Intel Macs are not supported.

Step 2

Check the fingerprint

Before installing, you can verify that the DMG you downloaded is byte for byte identical to the file published in the GitHub release. A checksum is a fingerprint of a file: Prospector Lite publishes a SHA-256 fingerprint for each release file, and if the fingerprint of your copy matches the published value, the download has not changed since it was released.

SHA-256 is the recipe that computes the fingerprint. It reads every byte of the file and turns them into a 64-character code. Changing even a single byte anywhere in the file produces a completely different code, so a matching code means an identical file. The macOS build is not signed or notarized yet, which makes this check the real integrity test before you open anything.

Run the check

  1. Open Terminal: press Command + Space, type terminal, and press Return.
  2. Move Terminal into your Downloads folder:
    Terminal
    cd ~/Downloads
  3. Ask shasum to check your files against the published list:
    Terminal
    shasum -a 256 -c SHA256SUMS.txt --ignore-missing
  4. Read the result. You want exactly this line:
    Expected output
    ProspectorLite-5.0.0-macos-arm64.dmg: OK

What the pieces mean: -a 256 selects the SHA-256 algorithm, -c tells shasum to check files against a list instead of printing new fingerprints, and --ignore-missing keeps it quiet about the other release files named in the list that are not in your folder.

What OK means

OK means the bytes on your disk are identical to the bytes we released: nothing altered the DMG between our release pipeline and your Downloads folder, and the download completed fully. It says nothing about whether you trust the software itself; for that, the source code and the trust documentation are public.

If the line ends in FAILED instead, the file is not the released build. An interrupted download is the usual cause. Delete the DMG, download it again from the release page, and re-run the check. If it fails twice, stop and report it; do not open the file. A failure looks like this:

Output on a corrupted file
ProspectorLite-5.0.0-macos-arm64.dmg: FAILED
shasum: WARNING: 1 computed checksum did NOT match

The two common errors

  • Terminal is in the wrong folder, or the list is not there:
    Error output
    shasum: SHA256SUMS.txt: No such file or directory
    Run cd ~/Downloads again, then ls to list the folder. If SHA256SUMS.txt is not in the listing, it was saved somewhere else or under another name (see below).
  • The list is there but the DMG is not:
    Error output
    shasum: SHA256SUMS.txt: no file was verified
    The list was read, but none of the files it names exist in this folder. Usually the DMG is still downloading, was saved elsewhere, or was renamed.

If your browser renamed the checksum file

Downloading SHA256SUMS.txt a second time saves it as SHA256SUMS (1).txt instead of overwriting the first copy. Two fixes, both fine:

  • In Finder, delete the older copy and rename the new one back to SHA256SUMS.txt, or
  • Point the command at the renamed file, keeping the quotes:
    Terminal
    shasum -a 256 -c "SHA256SUMS (1).txt" --ignore-missing
    The quotes keep the space and the parentheses as part of one filename; without them, the shell reads three separate words and the command fails.

Or compare by eye

To see the raw fingerprint of your DMG:

Terminal
shasum -a 256 ProspectorLite-5.0.0-macos-arm64.dmg

It must match the published value, every character of it:

878cbff01e8bb2b597a2dfdb1c3a613406895cd59d933dc941a5ccf3fd5f6562

This value comes from the release's SHA256SUMS.txt, produced by the build pipeline at release time. The copy in your Downloads folder should contain exactly the same lines.

Step 3

Install and open it

  1. Double-click ProspectorLite-5.0.0-macos-arm64.dmg. A window opens with Prospector Lite and an Applications shortcut.
  2. Drag Prospector Lite onto the Applications shortcut.
  3. Eject the disk image (the eject icon next to its name in the Finder sidebar) and open your Applications folder.
  4. Right-click (or Control-click) Prospector Lite and choose Open, then click Open in the dialog.

If macOS only offers "Move to Trash"

The build is unsigned and not notarized yet, so Gatekeeper warns on the first open; that warning is expected on a genuine copy, and your matching checksum from step 2 is the evidence. On macOS 15 Sequoia and newer, the first dialog often has no Open button at all. The path through:

  1. Click Done (not Move to Trash).
  2. Open System Settings › Privacy & Security and scroll to the bottom of the page.
  3. Next to the line saying Prospector Lite was blocked, click Open Anyway, then confirm with Open.

This is a one-time step; afterwards the app opens normally. Never disable Gatekeeper itself, and treat an "app is damaged" message as a checksum problem: re-run step 2 on a fresh download rather than looking for a bypass.

Step 4

Grant the three permissions

First launch opens a five-page setup wizard: Welcome, Trust and Permissions, Guided Calibration, Readiness Check, then the app. The Trust and Permissions page holds one card per permission, and each card explains what the capability reads, what stays on disk, and what leaves your computer (nothing) before you grant anything. Prospector Lite asks for exactly three permissions and nothing else:

Screen Recording

Reads the game's bars and prompts from the screen. On recent macOS the pane is labeled "Screen & System Audio Recording"; the app captures pixels only and has no audio code.

Accessibility

Lets the app press keys and mouse buttons, the same events your own hands would produce. Output only; it does not observe your input.

Input Monitoring

A listen-only tap so the Esc Safe Stop works even while Roblox has focus. It watches for the stop hotkeys only and never logs what you type.

For each card: click Request (the only thing that ever triggers a system prompt), flip the switch for Prospector Lite in the System Settings pane that opens, then click the card's Test to prove it works. All three panes live under System Settings › Privacy & Security.

Restart after granting. macOS applies Screen Recording, and sometimes Input Monitoring, on the app's next launch. If a Test still fails right after you flipped the switch, quit fully with Command + Q and reopen the app.

Declining a permission never breaks the app: everything stays usable except Start Macro, which stays disabled with a message naming exactly what is missing. Deeper details, including the code behind each capability: Trust and permissions.

If something fails

  • A permission Test fails right after granting. Quit fully with Command + Q and reopen; macOS applies Screen Recording on the next launch. See macOS install issues.
  • "Prospector Lite is damaged and can't be opened." Delete the app, re-download the DMG, and re-run the step 2 check before installing again.
  • The permission is on but the app says it is missing. Remove Prospector Lite from the pane with the minus button, then Request again from the app's card so the fresh entry points at the installed copy.
  • Anything else. The Troubleshooting and FAQ page covers detection, timing and permission symptoms one by one.
